# QR Scanner (PWA)

An installable Progressive Web App that scans QR codes with your camera, extracts the session UUID from each code, and registers a visitor against your backend API.

Built with Next.js (App Router), TypeScript, Tailwind CSS, and [jsQR](https://github.com/cozmo/jsQR).

## Features

- Camera permission flow that works on iPhone (Safari) and Android: tap **Allow Camera Access** to request permission on a user gesture
- **Image** upload fallback for cameras that are unavailable or blocked over plain HTTP
- Robust QR decoding via ZXing (with jsQR fallback) — works with real-world photos, perspective distortion, and iOS HEIC images
- Live camera scanning with animated focus frame and scan line
- Image upload fallback for cameras that are unavailable or denied
- On scan, the session UUID is extracted from the QR content (the `hm-` prefix is stripped) and a visitor registration form is shown
- Form fields: name, email, phone, visitor type, existing/new visitor, company name, optional website, and the scanned session UUID
- Recent-scan history persisted in `localStorage` (tap an entry to re-inspect it)
- PWA: installable on mobile/desktop, offline app shell via a custom service worker
- Server-side proxy to your API (avoids CORS) with optional bearer-token auth

## Getting Started

```bash
npm install
cp .env.local.example .env.local   # then edit VISITOR_API_URL if needed
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Camera access requires HTTPS or `localhost`. To test on a phone over your LAN, serve over HTTPS (e.g. a tunnel) — iOS and Android block camera access on plain HTTP.

## Configuration

`.env.local`:

| Variable           | Purpose                                                                   |
| ------------------ | ------------------------------------------------------------------------- |
| `VISITOR_API_URL`  | Visitor registration endpoint. Defaults to `http://10.1.1.114:8000/visitors/general`. |
| `API_KEY`          | Optional. Sent as `Authorization: Bearer <API_KEY>`.                      |

The client posts the form to the local proxy at `/api/visitors` (`app/api/visitors/route.ts`), which forwards to `VISITOR_API_URL` server-side — no CORS issues and your backend stays private.

### Flow

1. Tap **Allow Camera Access** to grant camera permission (required on iOS).
2. Point the camera at a QR code (or upload an image).
3. The UUID is extracted from the code (`hm-<uuid>` → `<uuid>`) and the registration form opens.
4. Submitting the form POSTs the payload to the visitors API.

### API response handling

- `2xx` → result shown as **Registered** (green)
- non-`2xx` → shown as **Failed** (red)
- A string field named `message`, `msg`, `error`, or `detail` in the response body is displayed as the status text; otherwise the raw body is shown.

## Icons

PWA icons are generated by `scripts/generate-icons.mjs` (a dependency-free PNG encoder). Regenerate with:

```bash
node scripts/generate-icons.mjs
```

## Project structure

```
app/
  manifest.webmanifest   # PWA manifest
  api/visitors/route.ts  # API proxy (POST visitor payload)
  layout.tsx             # metadata, theme, apple icons
  page.tsx               # renders <Scanner/>
components/
  Scanner.tsx            # camera permission, camera loop, decoding, form flow
  VisitorForm.tsx        # visitor registration form
  ResultCard.tsx         # success/error result UI + actions
  ServiceWorker.tsx      # registers public/sw.js
  Icons.tsx              # inline SVG icons
lib/
  qr.ts                  # session UUID extraction from QR content
  scanApi.ts             # client → /api/visitors + response message parsing
  types.ts
public/
  sw.js                  # offline app-shell service worker
  icons/                 # generated PWA icons
scripts/
  generate-icons.mjs
```
